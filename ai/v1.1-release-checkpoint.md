# PX AI-Ready Design System — v1.1 Release Checkpoint

**Status: READY FOR BROADER DESIGNER USE.**

This is a scannable checkpoint, not a manual. For full detail, follow the links at the bottom.

## What v1.1 achieves

Generate a correct, on-brand PX screen from a plain product description alone — no Figma, no shell/token/registry vocabulary required from the requester.

## Architecture (bottom to top)

- **ShadCN/Radix** — behavior + accessibility foundation
- **Prism tokens + icons** — PX visual identity
- **Approved / provisional PX components** — typed, reusable pieces (`src/components/ui`)
- **Patterns / shells** — page-level composition (`src/patterns`)
- **Natural-language screen generation** — Claude composes the above from a plain request

## The 4 supported shell/archetype families

| Family | Shell | Anatomy |
|---|---|---|
| List | `PxListShell` | table/master dataset + filters |
| Detail/Drilldown | `PxDetailDrilldownShell` | single-record read view |
| Create/Edit | `PxCreateEditShell` (Modal / Accordion / Wizard) | record creation/edit, tiered by field count/branching |
| Analytics | `PxAnalyticsSecondaryNav` | KPI/chart dashboard |

## v1.1 hardening outcomes

- **Product Surface Rule** — shadow vs. border by surface context, PX-wide
- **`TableFrame`** — standard table toolbar/surface composition
- **Max-4 `StatsRow`** rule enforced
- **`DropdownMenu` scoped composition** — named, sanctioned internal consumers only
- **`Popover` scoped composition** — same treatment
- **`Input`/`PxHeader` scoped composition** — same treatment
- **Dependency-consistency CI check** — automatically catches the next instance of this class of gap (`scripts/validate-dependency-consistency.mjs`)

## Known non-blocking limitations

- Many shared components are still `Mapped-review-pending` (usable, not yet design-owner visually reviewed)
- No generic `FormField` wrapper yet (documented interim workaround exists)
- Dual-axis chart capability: deferred
- Page-level "supporting description" typography: deferred
- `src/pages/audience-explorer.tsx` is legacy/orphaned — never canonical, not routed
- Visual fidelity always benefits from a final designer look — this system gets structure/composition right, not final pixel sign-off
